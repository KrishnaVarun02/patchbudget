# Claim-to-evidence audit

All quantitative manuscript macros and tables are generated by `scripts/analyze.py`
from executed evidence. No resume metric or invented experiment is used.

| Claim | Evidence and rule |
|---|---|
| 16 algorithms, 241 candidate implementations | `results/full/inventory.json`; count programs and sum `candidates` |
| 116,640 selection records | `results/full/selections.csv`, excluding header; these are repeated policy/ranking/settings, **not independent bugs** |
| Main focused useful 93.125%, false 3.75%, coverage 96.875% | `summary.json`: gate=`one`, policy=`candidate_focused`, budget=32, minimum=8 |
| Round robin useful 62.0833%, false 1.4583%, coverage 63.5417% | Same key with policy=`round_robin` |
| Existing-only useful 32.5%, false 67.5% | gate=`one`, policy=`existing_only`, budget=0, minimum=0 |
| Failure-count useful 93.3333%, false 3.75% | gate=`one`, policy=`failure_count`, budget=32, minimum=8 |
| Useful difference 31.0417 percentage points, interval [12.2917,51.25] | `primary_comparison.json`, useful_coverage; paired program-level bootstrap, 5,000 draws |
| False-acceptance difference 2.2917 points, interval [-2.2917,10] | `primary_comparison.json`, false_accept; interval includes zero |
| Primary policies all spend 32 queries | Same summary rows, `queries`; excludes shared gate and offline matrices |
| Budget and threshold figures | `summary.json`, each plotted policy/gate/budget/minimum; `scripts/analyze.py` |
| 64 verifier + 256 hidden cases per algorithm, exact disjointness | `results/full/matrices/*.json`, verified by `scripts/verify.py` |
| Reference passes every retained case | Candidate with origin=`reference` in each matrix; verifier assertion |
| One excluded original developer case | `matrices/knapsack.json`, `official_exclusions`, with exact input, SHA-256 and resource reason |
| Timing and environment | `results/full/manifest.json`; matrix `execution_seconds` / `oracle_seconds`; times are observations, not speedups |
| Actual execution, not mocked results | `scripts/run.py` executes bounded Python candidates; independent code replay described in verification records |

`useful_coverage` and `false_accept` average ranking seeds within algorithm and
then algorithms equally. Conditional agreement is their corresponding
acceptance-weighted ratio, not average per-program precision. Every row of the
full policy CSV is independently reconstructible from the matrices. Figures are
descriptive; no hypothesis-test significance or novel algorithm claim is made.

## Independent review

A separate agent reconstructed and executed 1,446 candidate/test cells, verified
all 116,640 selection records, replayed 3,888 seed-0 policy settings, and recomputed
all 243 aggregate settings. All matched. The repository's own verifier additionally
replays every policy selection. A fresh Python 3.14 environment reruns the full
matrix for clean reproduction; its report is `results/clean-verification.json`.

## What the evidence cannot establish

Semantic correctness; performance on real AI-generated repository patches;
realistic oracle availability; runtime speedups; generalization across generated
test suites or software projects; superiority to full published systems; novelty,
submission readiness, acceptance or endorsement.
